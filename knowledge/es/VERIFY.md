# VERIFY · Validación y mantenimiento
- Ejecuta `python -m unittest -v`. Las pruebas cubren banda/gris, giros omitidos, caché local, adopción y MCP con datos simulados. La compilación comprueba la terminal empaquetada en las cinco plataformas.
- Al cambiar una regla, actualiza el mismo ID en los tres idiomas. Actualiza enlaces o entradas del índice cuando corresponda y ejecuta la suite. Para verificar Mainnet, consigue autorización aparte y comprueba la posición real.
- Antes de aprobar un cambio de lógica, compara la versión en producción y la candidata con el mismo archivo local de perpetuos de Lighter, usando las mismas fechas, costes, tamaño, apalancamiento y protecciones. Usa el [escenario de referencia](BACKTEST.md) y reserva una ventana de validación antes de las pruebas. Exige un ROI de referencia estrictamente mayor y sin regresión en validación. Registra ROI, caída máxima, operaciones y comando de reproducción. Con ROI igual, menor o sin evidencia, se conserva la regla vigente.
- Las pruebas de software verifican el comportamiento. El README publica solo el ROI simulado de la estrategia vigente con datos de Lighter. Los datos privados, diagnósticos y credenciales quedan fuera de Git.
